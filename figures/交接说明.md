   - **只列本领域**（LoRR 程序和仓库多机器人研究），按派单、选路、规划和避碰、窄道和拥堵处理四类分。

4. **我们的想法：试试计算机网络**：
   - 先说现象像在哪里，再说为什么偏偏想到计算机网络：领域成熟、算法多，而且我们是计算机专业。

6. **调度方向的优化**：名额、门口规则、执行器修复、两个兜底。每项按“现象 → 生活类比 → 想到的网络机制 → 哪里不同 → 别的领域的类似做法 → 怎么做（含计算）→ 结果”写。四个公式拆开，各放在对应的优化里。
7. **结果**
8. **哪些真正有用，换一张图还行不行**
9. **没成功的尝试**：两个阶段全部逐项列出，写结果和原因，再总结教训。用户原话：“没有功劳也有苦劳”。

## 五、怎么重新生成

```bash
# 简明版 / 第三部分 Word（注意：不要加 --metadata title，会乱码）
pandoc figures/brief/全文简明版_源稿.md -o SEEM5910_全文简明版_中文_vN.docx --resource-path=.
pandoc figures/part3/第三部分_源稿.md -o 第三部分_关键迭代与实验图解_vN.docx --resource-path=.

# 逐页检查（交付前必须做）
soffice --headless --convert-to pdf --outdir <临时目录> <文件>.docx
pdftoppm -r 60 -png <临时目录>/<文件>.pdf <临时目录>/p

# PPT：pptxgenjs 要先装到临时目录（npm install pptxgenjs），再用 NODE_PATH 指过去
# PPTX_SKILL 指向 pptx skill 的目录（要用它的 scripts/apply_theme.js）
NODE_PATH=<临时目录>/node_modules PPTX_SKILL=<pptx skill 目录> DECK_OUT=SEEM5910_演讲PPT_vN.pptx node figures/deck/build_deck.js
# 讲稿 Word：先把 PPT 转成图片放到 figures/deck/slides/slide-NN.png，再
python3 figures/deck/make_script_doc.py vN
pandoc figures/deck/演讲稿_源稿.md -o SEEM5910_演讲稿与幻灯片_vN.docx --resource-path=.
```

仿真程序（需要重跑实验时用）：

- 源码在 `experiment-materials/网络协议方向/src/dev_src_p78`，要在 `/home/user/simbuild` 这类**非 /tmp 目录**里编译，在 scratchpad 里编译会失败。
- 运行脚本在 `figures/part3/rerun/run.py`。
- 注意：全图上限依赖门口规则（`ACTIVE_CAP_GATE=2`）。单独测全图上限时，要设 `ROBOT_ACTIVE_CAP_GATE=0`。

## 六、踩过的坑

- **重排图号时只能改真正的图号。** 曾用正则把所有“图 N”加一，把“GenH 图 249 台”改成 251、“房间图 1000 台”改成 1001（v9 已修）。正确做法是先把 `![图 N]`、`**图 N**`、`（图 N）` 换成占位符，再按出现顺序重编。
- **pandoc 表格列太窄时**，用分隔行的短横线数控制列宽，例如 `|--|------|-------|----------|`。
- **LibreOffice 预览里占位符标题默认居中**，模板里要写 `align: "left"`。
- **原因没有查清的，就写“没有查清”**，不要补推测。例如预判跟进为什么变差、协议第 21 轮回归失败。

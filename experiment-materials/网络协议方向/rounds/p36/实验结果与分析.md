# 协议第 36 轮（项目 111）实验结果与分析：PFC + ECN + DCQCN 分层配合——ECN/DCQCN 先量跳过；“门还在过车就不放行”的看门狗 K=300 **确认通过**

## 结论先说
1. **ECN / DCQCN 源头降速：先量跳过。** 22 次门口僵局开始前 10 拍，门口“挤”（S1 ≥ 5，标记 19.2% 的过门）的只有 3/22 = 14%，“两头都挤”（S2 ≥ 2，标记 17.0%）的只有 2/22 = 9%，都低于事先写定的 60% 线。僵局开始时门口中位 3 台车，和平时一样；13/22 次门口只有一侧有车。数据中心里 PFC 只在快满时暂停，压住队列（DCQCN）就能防死锁；这里门口规则轻载时也在起作用，压队列管不到僵局。
2. **看门狗 + 排水条件（交换机看门狗的第二个条件）：** `ROBOT_PFC_WD=K ROBOT_PFC_WD_DRAIN=1`。开发（规划种子 103、104，每图 10 局）：
   - K=100：+1.58% [−0.25, +3.42]，最差 roomGB −7.90% → **没过**；
   - K=300：+0.64% [−0.12, +1.61]，最差 roomGB −1.42% → **过了开发判据**。
3. **确认（K=300，新种子 11800–11809 × 149、150，官方 8 + 留出 12，每图 20 局）：+1.73% [+0.50, +3.21]，最差 roomUE_240 −0.61%，800 次 0 错误 → 确认通过。** 网络协议方向第一个通过确认的机制。
4. **要写明的两点：**
   - 排水条件本身看不出贡献：同样种子上不加条件的看门狗 K=300 是 +0.72%（最差 −1.38%），K=100 是 +2.23%（最差 roomGB −9.33%），和加条件几乎一样（图 `p36_gate_vs_plain.png`）。room250 一局里条件只拦下 25 车·拍、放行 575 车·拍。确认的是“K=300 看门狗 + 排水条件”这个整体，不能说排水条件有用。
   - 好处集中在门口容易僵住的房间图：roomUB_194 +11.21%、roomUD_194 +6.39%、roomUA_253 +6.11%、roomUD_247 +4.62%（区间都在 0 以上）。官方三张房间图 −0.46% 到 +0.27%；maze / random / warehouse 正好 0（门口规则不起作用，看门狗不出手）。

## 三件事
- 层：物理层 / 链路层（门口规则 = PAUSE，门 = 队列，过门 = 发包）。
- 损失：门口僵局让整扇门停摆（第 35 轮先量：平均 9.0% 的时间有门口对峙）。
- 上限：协议里估 0 到 +0.5%；确认 +1.73%，比估计大，主要来自留出房间图。

## 为什么
1. **ECN 没有信号**：僵局是两三台车在门口按规则互相等，不是排队排出来的。
2. **排水条件很少起作用**：车站满 300 拍时，所在的门基本也真的 300 拍没过车，所以条件几乎不拦。第 35 轮 roomGB 的掉分，看来不是“正常排队被误放行”。
3. **为什么第 35 轮没过、这一轮过了**：同一个 K=300 看门狗，在规划种子 101、102 上 roomGB −3.79%，在 103、104 上 −0.97% / −1.42%。看门狗一局只出手几次，roomGB 这类图对小扰动很敏感，最差图会随种子摆动。确认用了 20 张图 × 20 局，平均和区间更稳；留出房间图上门口僵局多，看门狗救回来的局多。
4. **预测哪里错了**：预测“放行减少一半以上”错（几乎不减）；预测“确认不过”错。

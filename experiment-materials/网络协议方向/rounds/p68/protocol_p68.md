# 协议第 68 轮（项目 143）：MPLS-TE 自动带宽 → 按实测调割名额（S-4）

写于 2026-11-03T01:10Z，实验前提交。

## 出处
- MPLS-TE（RFC 3209，RSVP-TE 建 LSP、带宽预留）；有状态 PCE（RFC 8231，PCE 按实测流量更新 LSP 参数）。
- “自动带宽”（auto-bandwidth，各厂家实现，思路在 RFC 8231 的“按实测调 LSP 带宽”用例里）：路由器每个**采样间隔**量一次 LSP 的实际流量，每个**调整间隔**取其中的最大值；实测和当前预留差超过**调整阈值**（常见默认 5%–10%）就把预留调过去；中途连续若干次**溢出**（实测超过预留）可提前上调。
- 在网络里解决什么：预留是人配的，配小了流量被卡（LSP 带宽不够，丢包/走次优路径），配大了浪费链路。按实测慢慢调，让预留跟着需求走。

## 作用层 / 管的损失 / 上限
- 作用层：拓扑层准入（割 = 一组门把图分成两半，“割名额” = 每割每方向允许在途的车数 K，按带宽时延积定，即 LSP 预留）。
- 管的损失：第 67 轮先量——最忙门饿着（门格没车、门口区没有干活车）的门时间里，同时有车被割名额卡着的部分：**4.98%** 门时间（17 图平均；最高 roomFF 12.3%）。
- 上限：最多把这 4.98% 门时间变成过门；按门是瓶颈，完成数上限约 +5%，实际远低（见预测）。

## 改动（`src/dev_src_p68`，从 dev_src_p62 复制）
- 开关 `ROBOT_AUTOBW=1`（默认关）；参数 `ROBOT_AUTOBW_W`（调整间隔，拍）、`ROBOT_AUTOBW_TH`（溢出阈值）、`ROBOT_AUTOBW_MAX`（最多加几，默认 2）。
- 每拍（executor 每拍调用的 cd_tick 里）对每个单车道割（b < br_n1）每个方向 s 采样一次：“饿着且被卡” = 门正为这个方向服务但门口区、门格都空（沿用第 16 轮 `pipe_idle`）**且**这一拍里有车因为这个割这个方向的名额满被拒。
- 每 W 拍：饿着且被卡的拍数 / W > θ → 这方向加成 +1（不超过 MAX）；≤ θ/2 → 加成 −1（不低于 0，回到原 K0）。实际名额 = K0 + 加成。
- 和以前的区别：第 16–18 轮流水线是**快环**（门空的那一拍瞬时多放一台）；第 35 轮是全程放大 K；第 42 轮放宽的是全局名额；第 58 轮 R-3 只量没改。本轮是**慢环**、按窗口实测、有上限、会退回。

## 取值（事先定，不按成绩挑）
- A：W = 600 拍（200 步），θ = 0.05（自动带宽常见调整阈值 5%），MAX = 2。
- B：W = 600 拍，θ = 0.10（10% 档），MAX = 2。
- W 取 600 拍：采样间隔 = 1 拍，自动带宽常见“调整间隔 / 采样间隔”约 12–288 倍，这里取 600 / 3 = 200 步，在范围内；不再试别的 W。

## 预测
- 偏向没过（平均 −0.5% ~ +0.3%）：被卡几乎一直存在（97.8% 的时间），“饿着同时被卡”不保证多放的车能及时赶到门口（第 16–18 轮的教训）；多放的车反而在门口区排队，触发门口堵。可能 roomFF、room200 小涨，单门大图小跌。

## 在今天的骨干网里怎么用
- 自动带宽仍是 RSVP-TE 骨干网的标配：运营商常用 5 分钟采样、几小时到一天调整一次、5%–10% 阈值，配合 make-before-break 换新 LSP，不断流。缺点是反应慢、调整时会引起 LSP 重路由抖动，所以要设阈值和最小调整间隔。
- 新一代用有状态 PCE / SR-TE 控制器（例如 SR Policy + 遥测）集中算，按实测流量矩阵周期性下发，本质相同：慢环跟踪需求，快速故障交给 FRR。

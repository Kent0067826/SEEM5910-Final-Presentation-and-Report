# 协议第 70 轮先量 G-1：最忙门以外的门口区等待（事先写定）

写于 2026-11-03T03:05Z（测量前）。

## 为什么量这个
第 58–66 轮路由器层的骨干网机制（RSVP-TE 抢占 / 软抢占 / make-before-break、PCE 主动下发、IS-IS 过载位）全部只在**最忙的那扇门**上量，都不到 2% 线。
但骨干网里 RSVP-TE 的接纳控制和抢占是**每一跳都做**的，不只在最堵的那条链路上；17 图平均每任务过 3.6 扇门，第 29 轮说 55% 的过门在多门簇上。
第 43 轮账本里“门口区等”7.32% 车·拍是所有门加起来的，从来没拆过“最忙门 / 别的门”。如果别的门占大头，以前那些门口机制就该在所有门上重量。

## 作用层 / 损失 / 上限
路由器层（门簇 = 路由器，门口区 = 端口）；管账本“门口区等”7.32% 车·拍里最忙门以外的部分；上限就是这部分本身。

## 定义（离线，`~/robotnet-lab/work/p38/full` 17 份 LCAPWD 完整轨迹，分类同第 27 轮 ipfix_account.py）
- 每个“门口区等”的车·拍，归给离它最近的门（门格连通块；BFS 距离 ≤ 3），最忙门 = 过门次数最多的门。
- 第一步：最忙门以外的门口区等，占全部车·拍（17 图平均）。
- 第二步（同一次跑，只在第一步过线时才用于判断）：其中那一拍**那扇门的门格上没有车**的部分（门空着却在门口等 = 门口规则 / 预留能管的上限；门里有车时是正常排队，服务时间改不了）。

## 跳过线（事先定）
- 第一步 < **2.0%** 车·拍 → 跳过 G-1（以前只量最忙门的做法不漏大头）。
- 第一步 ≥ 2.0%、第二步 < **2.0%** → 跳过（别的门的等待多半是门里有车的正常排队）。
- 两步都 ≥ 2.0% → 下一轮按 RSVP-TE 逐跳接纳控制 / RFC 5712 软抢占在所有门上写协议。
- 另报最忙门的同口径数字作参照。

## 补充第三步（写于 2026-11-03T03:05Z，第一、二步结果出来后、第三步测量前）
第一、二步 17 图平均：别的门 6.19%、其中门格空着 3.80%，两步都过 2.0% 线（结果见 `g1_measure.json`）。
但“门口区”只是离门 ≤ 3 步的房间格，站在那里的车不一定要过这扇门（可能在等房间里别的车）。所以在写协议之前加一步细化：
- 第三步：第二步里，那台车**接下来进入的第一扇门就是这扇门**（从轨迹往后看）的部分。
- 另报：其中它面前那一格（下一次真正移动去的格）此刻被别的车占着的比例（被前车挡 = 排队，不是门的规则）。
- 跳过线：第三步 < **2.0%** 车·拍 → 跳过 G-1；≥ 2.0% → 下一轮写协议（RSVP-TE 逐跳接纳控制 / RFC 5712 软抢占在所有门上），协议里再按“被前车挡”的比例写清上限。
